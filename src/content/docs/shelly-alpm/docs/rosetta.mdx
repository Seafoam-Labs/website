Shelly Rosetta compares Shelly and Pacman commands. Shelly appears first; the marker in **Purpose / notes** describes the match:

- **`=`**: equivalent operation and package scope for the stated inputs; formatting and prompts can differ.
- **`≈`**: similar purpose, with a meaningful difference explained in the row or linked notes.
- **`—`**: no direct counterpart in the other tool's documented CLI.

Replace uppercase placeholders before running examples; see the [argument key](#argument-key).

The **Short code** column is another spelling of the Shelly command in the same row, not a Pacman-compatible flag set. Some long flags stay separate to avoid ambiguous combinations. These examples target **Shelly 3.1.9**; see the [sources](#sources).

Shelly's `standard` backend covers ALPM packages, including configured third-party repositories. Removal matches assume ordinary, unheld ALPM packages. Shelly requests elevation when needed; privileged Pacman examples use `sudo`. Separate companion utilities are identified in their own table.

## Reading short codes

Most backend commands use an uppercase action and a lowercase backend: `I` = install, `U` = upgrade, `S` = search, `R` = remove; `s` = standard, `a` = AUR, `f` = Flatpak, `i` = AppImage. Not every combination is supported.

`shelly -Is PKG` means `shelly install standard PKG`. Adding `u` gives `shelly -Isu PKG`, which adds `--upgrade`. This is still only **similar** to `sudo pacman -Syu PKG`; Shelly uses separate upgrade and install transactions.

Modifier letters depend on the command. Keep global options separate (`shelly -Is PKG --no-confirm`). Append `h` for backend help (`shelly -Ish`), or use `shelly -I --help` for action help. The [CLI reference](/shelly-alpm/docs/cli-reference/) lists the available commands and options.

`shelly -U` upgrades **all enabled backends**; `shelly -Us` upgrades standard packages only. Likewise, `shelly -P` lists updates across all backends. Shared letters do not make Pacman flags interchangeable: `shelly -Rs PKG` uses Shelly's [removal defaults](#removal-and-orphans), not Pacman's `-Rs` behavior.

## Notes and sources

These notes explain the differences behind `≈` and the limits on `=`.

### Argument key

- **Targets:** `PKG` is an exact package name; `PKG…` means one or more selected names; `QUERY` is a search term; `REGEX` a regular expression; `GROUP` a package group; `DEP` a dependency name or expression; `VERSION` a version.
- **Backends and sources:** `REPO` is a configured ALPM repository; `REMOTE` a Flatpak remote; `APP_ID` a Flatpak application or runtime ID; `APPIMAGE` a tracked AppImage name. `FILE` is an Arch package archive, `OLDER_FILE` an older archive, and `FILE.AppImage` an AppImage file. `DB` is a standalone repository database such as `./repo.db.tar.zst`.
- **Other arguments:** `PATH` and `DIR` are filesystem paths; `FILENAME` a filename; `URL` a download or server URL; `KEY` a key identifier; `SERVER` a keyserver URL; `ARCH` an architecture; `NAME` a manifest filename without `.toml`; `CONFIG_FILE` a Pacman configuration file. Square brackets in explanations indicate optional arguments.

### Partial upgrades

Prefer `shelly upgrade standard` or `sudo pacman -Syu` for routine upgrades. Refreshing system databases without completing a full upgrade, then installing/updating selected packages, can leave incompatible versions. Arch Linux does not support partial upgrades. [ArchWiki: System maintenance](https://wiki.archlinux.org/title/System_maintenance#Partial_upgrades_are_unsupported).

`shelly update standard PKG` refreshes and updates only newer versions of named installed packages. `sudo pacman -Sy --needed PKG` can also install an absent target or downgrade a newer installed version. Both can create a partial upgrade. `pacman -Su PKG` upgrades the entire system.

### Installation and upgrades

Repository installation uses stored databases. Shelly also offers optional dependencies; with `--needed`, it offers them only for targets that still need installation. Both tools accept quoted version constraints through ALPM, but group selection, provider selection and optional-dependency handling can differ.

For local archives, Shelly's libalpm backend uses a fixed signature setting, while Pacman honors `LocalFileSigLevel`. This limitation does not describe Shelly's separate RLPM backend, which receives the configured signature policies. Shelly downloads HTTP(S) archives to a temporary file before archive installation. [libalpm archive implementation](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.PackageManager/src/alpm/libalpm_manager.zig#L1170-L1195), [RLPM signature configuration](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.PackageManager/src/rlpm/configuration.zig#L76-L78).

Shelly's standard upgrade force-refreshes databases and adds news, service-restart checks and a cache-cleanup offer. `install standard --upgrade` separates upgrade and installation transactions. `shelly upgrade all` covers every enabled backend: repositories, AUR, Flatpak and AppImage; Pacman covers repository packages. `sudo pacman -Su` uses stored databases; adding `PKG` also installs or upgrades that target, while still upgrading the whole system. [Upgrade implementation](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/upgrade.zig#L584-L651).

Shelly skips the standard upgrade transaction when its preliminary update list is empty. This also affects `install standard --upgrade`. With libalpm, that list checks newer versions of installed package names, so repository replacements alone may be skipped, whereas Pacman's full upgrade processes them. This possible limitation has not been tested in an upgrade transaction. [Upgrade pre-check](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/upgrade.zig#L604-L610), [installation pre-check](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/install.zig#L557-L564).

Shelly can mistake repository-qualified names containing dots, such as `REPO/dotnet-sdk-8.0`, for local file paths. [Target classification](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/install.zig#L1148-L1177).

### Update listings

Shelly's standard update listing refreshes a separate user-owned database. It excludes ignored packages and groups, and repositories without upgrade usage. `pacman -Qu` queries stored sync databases and can list updates marked `[ignored]`. `list-updates all` additionally checks AUR, Flatpak and AppImage; the standard-backend ignore filter still applies. [Listing implementation](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/list_updates.zig#L687-L700).

For AUR update listings, `--no-devel` skips checks of version-control sources and `--show-hidden` includes hidden packages.

### Search and metadata

Keep `shelly -Sa QUERY --standard` as written. `shelly -Sas QUERY` runs separate AUR and standard searches instead of appending high-confidence repository matches to the AUR results.

Shelly ranks text matches, paginates results and hides ignored packages by default; Pacman accepts regular expressions. These differences apply to repository and installed-package searches. `--show-hidden` includes ignored packages. Shelly's available-package listing also merges duplicate names across repositories.

For repository metadata, Shelly selects one matching repository entry; Pacman can show matches from multiple repositories. If a requested package is absent locally, Shelly's installed-detail search can fall back to repository metadata; `pacman -Qi PKG` reports an error.

`shelly list aur --show-hidden` returns foreign packages found in the AUR. `pacman -Qm` lists every package absent from configured sync repositories, including local packages and packages no longer in repositories.

### Removal and orphans

Shelly's default standard removal also removes unneeded packages installed as dependencies and suppresses `.pacsave`, matching `pacman -Rns`. Use `--no-cascade` to keep those dependencies and normal backup handling, matching `pacman -R`. Pacman also offers `-Rs` for dependency cleanup with `.pacsave`, and `-Rn` to suppress `.pacsave` without dependency cleanup. Shelly's documented standard removal options do not provide those two combinations. [Flag mapping](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/remove.zig#L312-L335).

Use `--ripple` together with `--no-cascade` to remove a package and its dependents. Otherwise, the default dependency cleanup takes precedence.

`--opt-deps` additionally selects optional dependencies for removal. Review the plan: some may still be optional for another application. `--remove-config` additionally removes the package-named directory under the user's configuration directory. Pacman's `-n` suppresses `.pacsave`; it does not delete application-created home settings.

AUR removal also clears the build cache and version-control tracking state. Unlike `remove standard`, it does not remove unneeded dependencies by default. For Flatpak removal, `--remove-unused` adds dependency cleanup and `--remove-config` adds application-data cleanup. For AppImage removal, `--remove-config` adds associated configuration cleanup.

Before removing orphans with Pacman, select the packages with `pacman -Qdt`. Shelly's orphan cleanup also removes corrupted cached archives and checks that selected packages are unneeded. Its dry-run preview includes those archives too.

### Cache cleanup

`shelly purify standard --cache 3` retains three recent archive entries per package name. `sudo pacman -Sc` uses `CleanMethod` and can also remove unused sync databases. With zero retention, Shelly removes recognized cached package archives and signatures; `sudo pacman -Scc` clears all package-cache files and can also remove unused sync databases.

`sudo paccache -rk3` offers similar retention, but how it counts and groups archives differs, as does corrupted-archive cleanup. `paccache` comes from `pacman-contrib`.

`pacman -Qk PKG` checks that installed files are present; `pacman -Qkk PKG` also checks their metadata. Shelly's `purify` checks cached archives instead. A standard dry run without other cleanup options previews corrupted archives only.

`--aur-cache` selects **everything in Shelly's cache, including AUR sources, build directories and checkouts**. Preview with `shelly -Zsd --aur-cache` and review every target before omitting `--dry-run`. This is separate from package-archive retention with `shelly -Zsc 3`. [Cleanup option](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/cli/catalog/purify.zig), [implementation](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/purify_aur_cache.zig).

### Backup and restore

Shelly exports repository packages, AUR packages and Flatpak applications grouped in TOML, but omits foreign packages absent from the AUR. `pacman -Qqe > packages.txt` exports all explicit ALPM package names. Neither backs up application data.

Import installs current repository packages, AUR packages and Flatpak applications from `DIR/NAME.toml`; it does not restore application data or historical package versions.

### Repository and settings changes

For choosing the native configuration file, editing options and checking repository definitions, see
[Native package configuration](/shelly-alpm/docs/native-configuration/).

Reading Shelly configuration can create or normalize its settings file. `ParallelDownloadCount` is a Shelly setting, distinct from Pacman's `ParallelDownloads` directive. Choose one operation per AppImage environment change: set, unset, clear or replace.

Quote ALPM repository URLs to preserve Pacman variables such as `$arch` and `$repo`. Adding or removing repository configuration also refreshes databases unless `--no-sync` is supplied. Flatpak remote changes default to system scope; `--system=false` selects user scope. AppImage update sources include StaticUrl, GitHub, GitLab, Codeberg and Forgejo.

For ignored packages (`IgnorePkg`) and packages protected from removal (`HoldPkg`), use `PKG --remove` to remove entries or `--clear` to clear the list. Clearing `HoldPkg` keeps Shelly's protected entry.

`shelly utility --repair-db` deletes the database lock, normally `/var/lib/pacman/db.lck`. It does not check whether the lock is stale. Confirm that no package manager is running first.

### Package and file queries

`pacman -Dk` checks local database consistency; `pacman -Dkk` checks that sync-database dependencies are available. These differ from `-Qk` installed-file checks. `pacman -Qq` gives names only rather than Shelly's richer JSON; `-q` simplifies several other query outputs too.

`pacman -Qt` excludes packages required either directly or optionally; `pacman -Qtt` also includes optionally required packages. Both include explicitly installed packages. `pacman -Qdtt` restricts the result to dependency-installed packages without hard reverse dependencies, including those still optionally required; `-Qdt` excludes the latter.

Machine-readable file-search output contains NUL-separated repository, package, version and path fields, in that order. `pacman -Fq FILENAME` gives names only.

### Dependency checks

Shelly's `--no-deps` sets ALPM `nodeps`, skipping all dependency checks. The Pacman counterpart is doubled `-dd`; single `-d` skips dependency version checks only.

`--force` skips all dependency checks for an ALPM package that is not protected by `HoldPkg`. It does not enable recursive cleanup or `nosave`, matching `-Rdd`. The help describes this flag for local binaries, but the [implementation](https://github.com/Seafoam-Labs/Shelly-ALPM/blob/v3.1.9/Shelly.Cli.Zig/src/commands/remove.zig#L312-L335) also applies it to ALPM packages.

### Transaction options

Flags apply only to the stated operations. `--assume-installed 'DEP=VERSION'` treats a dependency as satisfied without installing `DEP`. `--dbonly` changes database entries without changing package files; it is not a preview. `--noscriptlet` skips package install scriptlets but does not disable all ALPM hooks. These three options also apply to removal (`-R`) and archive installation (`-U`).

`--asdeps` and `--asexplicit` set the installation reason during installation, including with `-U`. The `-D` commands change the reason for already-installed packages. `--ignore PKG` and `--ignoregroup GROUP` exclude upgrades for one run; Shelly's ignore marks persist between runs and do not themselves perform an upgrade.

`--overwrite 'PATH/*'` also applies to `-U`; quote the pattern. It does not permit every directory/file conflict. Explicit `--dbpath` paths are absolute and are not automatically prefixed by `--root`.

Shelly documents safe automatic answers for `--no-confirm`; Pacman's `--noconfirm` bypasses confirmations. Pacman's `--confirm` cancels an earlier `--noconfirm`.

For printed transaction targets, `--print-format '%n %v'` customizes output. Adding `-y` still refreshes databases even though the targets are not committed. Quiet output depends on the operation; transaction output also supports `--noprogressbar`.

Pacman has separate controls for filesystem, syscall and hook or scriptlet network isolation: `--disable-sandbox-filesystem`, `--disable-sandbox-syscalls` and `--disable-sandbox-network`. `--disable-sandbox` disables the combined sandbox controls.

### Keys and repository databases

Shelly's default signing-key location and configuration can differ from Pacman's configured `GPGDir`. For received keys, Shelly's `--user` instead imports into the user's PKGBUILD source-signing keyring.

Shelly includes available package signatures when adding entries to a standalone repository database. Locking, publication and supported archive formats differ from `repo-add`; removing entries also handles locking differently. Neither `pacman` nor `repo-add` provides the same entry-listing command as Shelly.

Missing signatures for standalone databases or archives are reported as skipped. A successful verification exit does not authenticate an unsigned database.

### Builds and companion utilities

`shelly -Asl` means `shelly build --sync-deps --install`. The install modifier is `l`; `shelly -Ai` means `build --isolated`, **not** install.

Shelly fetches, reviews, builds and installs AUR packages. Pacman can install the resulting archive with `-U`, but cannot perform those earlier steps. `makepkg -si` builds the current directory's PKGBUILD, installs missing dependencies and installs the result. Build engines, configuration and defaults differ from Shelly.

`shelly build --review-only` evaluates PKGBUILD inputs and emits review data as JSON without building. It can evaluate build inputs rather than just display the file.

Pacfiles include `.pacnew`, `.pacorig` and `.pacsave`. `pacdiff --sudo`, from `pacman-contrib`, reviews and merges root-owned files with elevation. `pacdiff --output` only lists discovered paths.
