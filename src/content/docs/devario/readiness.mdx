Devario has a bootable Community image, an Aqueous and Pearl desktop,
Calamares installation, and Shelly package management. Hardware coverage and
release validation are ongoing; the source configuration does not guarantee
that every published image contains the latest changes.

## Hardware and installation

| Area                   | Current setup                                                                                                                             |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| CPU                    | x86-64-v3 target for the Devario kernel and image                                                                                         |
| Firmware               | BIOS or UEFI for live boot; **64-bit UEFI required for installation**                                                                     |
| Secure Boot            | Not configured by the image                                                                                                               |
| Intel and AMD graphics | Mesa and Vulkan drivers are included; check your hardware with the live desktop                                                           |
| NVIDIA graphics        | Open kernel modules for supported Turing-and-newer GPUs; Calamares checks the packaged driver's PCI support list before partitioning      |
| Older NVIDIA GPUs      | Unsupported by this image; Nouveau is blacklisted                                                                                         |
| External GPUs          | Bolt authorization tools and GPU hotplug handling are included; physical hotplug, display, and suspend/resume validation remain necessary |

## Software and release boundaries

- The base installation is offline. Repository downloads and updates need
  access to the configured software sources.
- Shelly's native RLPM backend is the Devario package engine. The optional
  AUR build toolchain is absent from the default desktop.
- Development images and public release images have different repository
  trust requirements. Public release builds require signed inputs.
- Calamares currently remains installed on the target system.
- Boot splash handoff, encrypted-root unlock, and hardware-specific behavior
  still need image-level acceptance testing.

The [OS README](https://github.com/Seafoam-Labs/devario-os#development-limitations)
tracks development limitations, and the
[test suite](https://github.com/Seafoam-Labs/devario-os/tree/main/tests)
covers image, installer, package, desktop, and boot behavior.

## Trying a live image or virtual machine

Try input, displays and networking in the live desktop before partitioning.
Then check the installer and a fresh boot separately.

For a VM, record the image checksum, hypervisor version, UEFI mode, CPU model,
GPU/3D backend and memory. The image needs the CPU target above, installation
needs 64-bit UEFI, and the virtual graphics path must support Vulkan. A generic
“3D acceleration” checkbox does not guarantee this. There is no single tested
Virtio/Venus setup or minimum VM memory recommendation here.

If both the desktop and installer disappear, collect crash diagnostics rather
than assuming you were logged out.

| Symptom                                            | Next check                                                                                                                                                              |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Live desktop works but installation will not start | Firmware mode, CPU target and the installer log/error; preserve the image checksum.                                                                                     |
| Repository or upgrade check fails                  | Network/time and [Shelly diagnostics](/shelly-alpm/docs/troubleshooting/); do not change repository families to bypass an error.                                        |
| No shell after login                               | [Package/session selection](/aqueous/desktop-session/#recover-a-missing-shell-or-failed-upgrade) and the matching managed unit.                                         |
| Wrong layout or failed login                       | [Greeter recovery](/pearl/docs/greeter/#wrong-keyboard-layout-or-failed-login); check the layout again after an upgrade.                                                |
| Freeze, game stall or logout hard-lock             | [Desktop failure collection](/pearl/docs/command-line/#when-something-fails), including the previous boot if available. No general logout hard-lock fix is established. |

## Diagnostics

Open **Devario Report** from the application menu, or collect a local report
in a terminal:

```sh
devario-report.sh --no-upload
```

The report includes hardware, scheduler information, kernel messages, boot
warnings, and Shelly's package inventory. The command saves
`devario-report.log` in the current directory; the menu launcher saves reports
under `~/.local/state/devario/reports/` by default.

Reports redact common personal details, but review the saved file before
sharing it. The interactive tool can offer a public upload; `--no-upload`
keeps collection local. See the
[report implementation](https://github.com/Seafoam-Labs/devario-os/blob/main/packages/devario-base/devario-report.sh)
for the collected fields and upload behavior.
