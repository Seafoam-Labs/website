Aqueous targets Linux and Wayland. The compositor, window-management policy,
input handling, and output management are compiled into one Zig executable;
there is no .NET runtime or separate window-manager service.

## Requirements

To build from source, you need:

- Zig 0.16 or newer
- wlroots 0.20, Wayland, wayland-protocols, libxkbcommon, libinput, libevdev,
  pixman, and pkg-config development files
- XWayland when building with `-Dxwayland`
- SceneFX when building with `-Dscenefx=true`

The reference Arch package declares the complete runtime and build dependency
set, including the session, portal, XWayland, and Noctalia components.

## Arch Linux

The reference Arch package installs the compositor, `aqueousctl`, the Wayland
session entry, portal integration, the default `wm.toml`, and Noctalia session
assets. Prebuilt packages are available from CachyOS and AUR; the repository
also includes a source `PKGBUILD` and binary-package recipes for published
builds.

### Build from source

<Tabs>
  <TabItem label="PKGBUILD">

    ```sh
    git clone https://github.com/Seafoam-Labs/Aqueous.git
    cd Aqueous
    makepkg -si
    ```

  </TabItem>
  <TabItem label="Build helper">

    ```sh
    git clone https://github.com/Seafoam-Labs/Aqueous.git
    cd Aqueous
    scripts/build-compositor.sh
    ```

    The build helper stages `aqueous` and `aqueousctl` under `bin/`. For a
    direct development build, run `zig build` from the `compositor/` directory.

  </TabItem>
</Tabs>

## Starting a session

<Steps>

1. Select **Aqueous** from your display manager's Wayland session list.

2. The packaged session starts Aqueous through UWSM, exports the live Wayland
   environment, and starts the graphical-session services.

3. To test a development build inside an existing Wayland session, run:

   ```sh
   ./launch_river.sh
   ```

</Steps>

<Aside type="note" title="The launcher name is historical">
  `launch_river.sh` starts a nested Aqueous session. The project no longer
  launches a separate River compositor or external window-manager client.
</Aside>

## First-run configuration

The packaged session creates `~/.config/aqueous/wm.toml` from the system
default when the file does not already exist. It never overwrites your copy.
The other three files are optional sidecars, so create only the ones you want
to customize:

```sh
mkdir -p ~/.config/aqueous

# When working from a source checkout:
cp layout.toml.example ~/.config/aqueous/layout.toml
cp input.toml.example  ~/.config/aqueous/input.toml
cp rules.toml.example  ~/.config/aqueous/rules.toml
```

The example files are heavily annotated references. For a smaller day-to-day
setup, use the focused examples in the [Configuration](/aqueous/configuration/)
guide and add sections only as you need them.
