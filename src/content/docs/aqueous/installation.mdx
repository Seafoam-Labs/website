Aqueous packages include the compositor, `aqueousctl`, session integration,
default configuration, a shell settings plugin and helper, protocol metadata,
and Aqueous's pinned wlroots library. Shell integration depends on the package
variant.

To build the Arch package from a checkout:

```sh
git clone https://github.com/Seafoam-Labs/Aqueous.git
cd Aqueous
makepkg -si
```

### Shell and package variants

| Source or package variant                                                          | Shell integration                                                                  |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `PKGBUILD`, `PKGBUILD-git`, `GitPKGBUILD/PKGBUILD`, Intel variants, `PKGBUILD-DMS` | Seafoam Labs' `dms-aqueous`, Aqueous Settings, and the DMS screen-sharing chooser. |
| `PKGBUILD-bin`                                                                     | Noctalia and its settings plugin; no welcome application.                          |
| `gitNoctalia/PKGBUILD`                                                             | Alternative `aqueous-git` build preserving Noctalia and Welcome.                   |
| NixOS module and Gentoo installer                                                  | Noctalia integration.                                                              |

The DMS integration targets DMS 1.7 or newer and uses the
[Seafoam Labs fork](https://github.com/Seafoam-Labs/DankMaterialShell).
The release `PKGBUILD` builds its version tag; Git variants track repository
development. Features documented from the current source may arrive in release
packages later.

### Switching an existing profile to DMS

Existing user configuration is preserved. Copy the launcher and screenshot
commands from `/usr/share/aqueous/wm.toml` into your own `wm.toml`:

```toml
[actions]
toggle_start_menu = "dms ipc call spotlight toggle"
screenshot = "dms screenshot region"

[keybinds.custom]
"Super+Shift+S" = "spawn:dms screenshot region"
```

Disable manually enabled shell services or shell startup commands before using
packaged startup. `GitPKGBUILD/PKGBUILD` starts `dms.service` through
`graphical-session.target`; the other DMS source variants use
`aqueous-dms.service`. When moving to the former, remove manual enablement of
the old `aqueous-dms.service` to avoid starting DMS twice.

DMS packages omit the Noctalia Welcome app. Enable Aqueous Settings in
**DMS Settings → Plugins** and use it for compositor configuration. Review any
portal `.pacnew` files or user overrides after changing shell variants, then
log out and back in. See [screen sharing](/aqueous/shell-integration/#screen-sharing-and-portals).

## Gentoo

The repository includes an installer that can install dependencies, build the
pinned compositor stack and settings helper, install the session, and verify
the result:

```sh
git clone https://github.com/Seafoam-Labs/Aqueous.git
cd Aqueous
sudo scripts/gentoo-install.sh all
```

Use `deps`, `build`, or `install` instead of `all` to run one stage. Existing
files under `/etc` are preserved; changed packaged defaults are written beside
them with an `.aqnew` suffix.

## NixOS

The `nix/` directory provides a package, overlay, and NixOS module. From a
configuration repository, import both the module and overlay:

```nix
{
  imports = [ /path/to/Aqueous/nix/module.nix ];
  nixpkgs.overlays = [ (import /path/to/Aqueous/nix/overlay.nix) ];

  programs.aqueous = {
    enable = true;
    package = pkgs.aqueous;
  };
}
```

Set `programs.aqueous.noctalia.enable = false` to install the compositor
session without enabling Noctalia. The Nix package intentionally excludes the
Arch/Shelly-focused welcome application.

## Build from source

Building requires Zig 0.16 or newer, wayland-protocols 1.49 or newer, wlroots
0.20 build dependencies, libxkbcommon, libinput, libevdev, pixman, Vulkan
headers and loader, Meson, Ninja, pkg-config, and glslang. XWayland builds also
need the `Xwayland` executable. Man-page builds use `scdoc`.

The repository helper builds the patched wlroots render hook and stages
`aqueous` and `aqueousctl` under `bin/`:

```sh
git clone https://github.com/Seafoam-Labs/Aqueous.git
cd Aqueous
scripts/build-compositor.sh
```

For a direct development build:

```sh
cd compositor
scripts/build-wlroots-render-hook.sh
export PKG_CONFIG_PATH="$PWD/.deps/wlroots-render-hook/lib/pkgconfig"
zig build -Doptimize=ReleaseSafe -Dxwayland -Dllvm
```

Useful build switches are:

| Option                   | Purpose                                                                                              |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `-Dxwayland=true`        | Build embedded XWayland support.                                                                     |
| `-Dvulkan-effects=false` | Diagnostic build without Aqueous blur or rounded corners; still requires the pinned patched wlroots. |
| `-Danimations=false`     | Compile out compositor-side placement and workspace motion.                                          |
| `-Dman-pages=true`       | Build and install manual pages when `scdoc` is available.                                            |
| `-Dexternal-policy=true` | Build the retired River external-policy path for compatibility testing only.                         |

<Aside type="caution">
  The normal effects build requires Aqueous's pinned wlroots render hook and
  Vulkan renderer. Keep the installed private wlroots library with the
  compositor instead of substituting a system wlroots build.
</Aside>

## Starting a session

<Steps>

1. Select **Aqueous** from the display manager's Wayland session list.

2. The packaged wrapper launches Aqueous through UWSM, exports the live
   `WAYLAND_DISPLAY` and optional XWayland environment, and starts the
   graphical-session services and portals.

3. On a fresh packaged profile, the session seeds `wm.toml` and starts the
   package's shell integration. The Noctalia Git variant also offers the welcome
   application. Existing configuration and bar layouts are not overwritten.

</Steps>

The compositor works with compatible shells using standard layer-shell
interfaces. Source Arch packages depend on `dms-aqueous`; choose the package
variant appropriate to your shell.

To run a nested development session inside another Wayland compositor:

```sh
./launch_aqueous.sh
```

The launcher starts Aqueous and DMS (`dms run`) in the nested display. Set
`AQUEOUS_COMPOSITOR_BIN=/path/to/aqueous` to select a build and
`AQUEOUS_DMS_CMD` to override the shell command and arguments. Default logs are
`/tmp/aqueous.log` and `/tmp/dms.log`.

## Runtime switches

`aqueous -help` lists the complete runtime interface. Common development
options include `-c <command>`, `-log-level debug`, `-no-xwayland`, and
`-xwayland-scaling native`. Shipped sessions use the internal policy; external
and comparison policy modes require the compatibility build option above.
